# PlayMint — AI Implementation Status


## TL;DR

PlayMint turns a text prompt into a playable browser game (Runner or Action Quest
platformer) with **all visual assets generated by AI at play time**. The pipeline is
live and verified on both provider paths:

| Path | Provider | Speed | Cost |
|---|---|---|---|
| **Primary** | Google Gemini (`gemini-2.5-flash-image`) | ~15–25 s per game | ≈ $0.35 per game |
| **Fallback** | Pollinations (free, keyless) | ~1.5–2 min per game | free |

No API key is required to play — without a key the app automatically uses the free
fallback. With a Gemini key you get faster generation, prompt-aware art direction,
vision quality control, and an animated player character.

## Quick guide for testing

### How to test

1. `npm install`, then `npm run dev` and open http://localhost:5173.
2. Add the Gemini API key (see next section) — via `.env` before starting, or via the
   **"Insert Gemini API key"** field in the top-right corner of the start screen.
3. Generate games with prompts that are NOT close to the built-in themes, so you can
   see real AI art direction (not template fallbacks). Good test prompts:
   - Runner: `city runner in an underground bunker fallout 76 inspired`
   - Action Quest: `ancient jungle temple quest with stone golem enemies, vine covered
     ruins and glowing spike traps` (select the **Action Quest** mode bubble)
4. What to check in the result:
   - The compile terminal lists each asset with its provider, e.g.
     `Ready: player via gemini (4/8)`, and ends with a summary line.
   - The player has an 8-frame run cycle with alternating legs plus a jump pose.
   - Sprites have a dark outline and contrasting colors; no white edges or boxes;
     three background layers scroll at different speeds.
   - In DevTools: `window.__GAME_LIVE_CONFIG.assetMeta` shows per-asset provider,
     attempts, QA verdicts (`facingRight`, `backgroundClean`, `legsAlternate`), and
     animation frame data.
5. To test the free path explicitly: run `localStorage.PM_FORCE_POLLINATIONS='1'` in
   DevTools, reload, generate again (expect ~2 min, static or occasionally animated
   player, no vision QA fields).

### Which API key / provider

- **Recommended: Google Gemini** — set `VITE_GEMINI_API_KEY` in `.env` (template in
  `.env.example`) or paste it in the start-screen field. Get a key at
  https://aistudio.google.com/apikey — it must be on a **billing-enabled** project,
  otherwise image quota is zero and everything silently falls back to the free engine.
  Cost is roughly $0.35 per generated game, ~15–25 s.
- **Pollinations** is the automatic free fallback — no key needed. An optional
  `VITE_POLLINATIONS_API_KEY` token speeds up its rate limits slightly.
- The key runs client-side by design (accepted tradeoff for this app; see
  Known limitations).

### What is currently working

- Full prompt → playable game flow in both modes (Runner, Action Quest), verified
  end-to-end on both providers.
- 8 AI-generated assets per game with guaranteed sizes and transparency; automatic
  retry/fallback so generation never hard-fails.
- Prompt-aware art direction (Gemini) with per-category color rules: muted backgrounds,
  dark silhouette parallax layers, saturated complementary accent colors for
  player/enemy/hazards, programmatic dark outlines — gameplay elements are readable
  against the scenery.
- Edge cleanup pipeline (erode → outline → color bleed) that removes white fringes both
  from the images and from GPU texture filtering.
- Animated player: 8-phase run cycle with alternating legs + dedicated jump pose,
  gated by geometry checks and vision QA (`legsAlternate`); free path gets one gated
  sheet attempt and a procedural motion fallback otherwise.
- Vision QA (facing, background cleanliness, sheet consistency) with client-side
  corrections; runs whenever a key is present, even if image quota is exhausted.
- Three-layer parallax, under-floor fill, share links, live tuning panel.

### What is still unstable / needs improvement

- **Free-path sheet lottery**: without Gemini, the animated player only succeeds when
  the free model happens to draw a well-aligned grid — most free runs get the static
  player with procedural motion instead. This is by design (gates reject bad sheets),
  but it means animation quality depends on the provider.
- **Gemini quota sensitivity**: heavy testing can hit per-day/per-minute limits; the
  run then silently degrades to the free path (check the provider summary line if
  results look worse than expected).
- **Occasional keying edge cases**: enclosed background pockets between a character's
  limbs can survive (deliberate tradeoff protecting white details like visors); rare
  gradient backdrops may leave minor artifacts despite the self-check.
- **Enemy is static** — animation machinery is built and reusable, not yet applied to
  the enemy slot.
- **Free path is slow (~2 min)** due to Pollinations' one-request-at-a-time limit;
  upstream constraint.
- **Production hosting** needs a `/api/pollinations/*` → `https://image.pollinations.ai`
  rewrite (the dev server provides it automatically); without it only the Gemini path
  works in production.
- **Client-side API key**: the Gemini key is visible to the browser; acceptable for
  demos/prototypes, but a production deployment should proxy Gemini calls server-side.

## What is implemented

### 1. Asset generation pipeline (`src/game/assetPipeline/`)

Every new game generates up to **8 assets** from your prompt:

- `background_far` — wide scenery backdrop
- `background_mid` — silhouette skyline strip (parallax middle layer)
- `background_near` — foreground props strip (parallax near layer)
- `floor` — seamless tileable ground texture
- `platform` — floating platform sprite
- `player` — the character (animated sprite sheet on the Gemini path)
- `enemy` — patrolling enemy sprite
- `obstacle` — hazard object

Key properties:

- **Prompt-aware art direction.** One Gemini text call (`gemini-flash-latest`) designs a
  style guide + per-asset subject descriptions from your prompt (e.g. "city runner in an
  underground bunker, Fallout inspired" produces bunker-themed subjects, not a generic
  city). Local keyword-matched theme tables cover the no-key path and any API failure.
- **Guaranteed dimensions and transparency.** No image model honors exact pixel sizes or
  outputs alpha, so a post-processing stage (pure canvas, `postprocess.js`) resizes,
  removes backgrounds via border-connected flood fill (works on any backdrop color, keeps
  white details inside sprites), and crops every asset to the exact contract the game
  engine needs.
- **Sprite-grade edge cleanup.** After keying, every sprite goes through the standard
  game-pipeline edge chain: erode the anti-aliased white fringe, stamp a dark outline
  under characters/hazards (the classic pixel-art readability guarantee), and bleed edge
  colors into transparent pixels so GPU texture filtering can't paint white halos.
- **Readability by design.** Following standard game color practice, backgrounds are
  prompted muted and hazy, nearer parallax planes are silhouette-dark (plus programmatic
  darkening for depth), and the art director reserves one saturated complementary accent
  palette for the player, enemy, and hazards — so gameplay elements pass the squint test
  instead of blending into the scenery.
- **Automatic retry & fallback ladder.** Each asset: Gemini (2 attempts) → Pollinations
  (2 attempts) → static theme asset. A failed optional layer (mid/near parallax) is
  simply dropped — generation never hard-fails.
- **Rate-limit awareness.** A quota circuit breaker skips Gemini for the rest of a run
  after a hard 429; Pollinations calls run through a strict serial queue (it only allows
  ~1 concurrent generation).

### 2. Vision quality control (`qa.js`)

After post-processing, a cheap Gemini vision call reviews the player and enemy sprites:

- **Wrong facing** → sprite is mirrored client-side (and the verified facing overrides
  the in-game pixel heuristic, which used to guess wrong).
- **Leftover background** → re-keyed with looser tolerances, then at worst one
  regeneration.
- QA is corrective, never fatal — any QA error and the sprite is used unverified.
- Vision QA runs whenever a Gemini key is configured, even when image generation itself
  fell back to the free provider (the vision model has separate quota) — so free-fallback
  sprites still get facing and background review on keyed installs.
- Independently of any API, a **deterministic keying self-check** measures leftover
  near-white backdrop on every keyed sprite and automatically re-keys with looser
  tolerances — this is what cleans up "white not cut" artifacts on the keyless path.

### 3. Animated player (both paths)

The player is generated as a **3×3 sprite sheet**: an 8-frame run cycle with alternating
legs (12 fps) plus a dedicated jump pose. Each cell is background-keyed individually,
frames are union-cropped so the animation doesn't jitter, and any quality failure falls
back to a static player sprite. Gemini produces reliable sheets; the free path gets one
gated attempt — a local geometry check (consistent frame sizes, no empty cells) accepts
or rejects it without needing a vision model. When the player ends up static, the game
adds a subtle procedural run bob so it never looks frozen.

### 4. Parallax backgrounds

Three depth layers scroll at different speeds in both game modes: cover-scaled far
backdrop, plus mid/near tiling strips pinned to the ground line. An under-floor fill
extends the ground to the bottom of the viewport.

### 5. Provider visibility

- The compile terminal on the start screen logs which provider produced each asset
  (`Ready: player via gemini (4/8)`).
- In the browser console, `window.__GAME_LIVE_CONFIG.assetMeta` shows per-asset detail:
  provider, attempts, final prompt, QA verdict, mirroring, animation frames.

## How to use

### Setup

```bash
npm install
npm run dev        # http://localhost:5173 — the only command needed
```

Optional but recommended — add a Gemini API key (get one at
https://aistudio.google.com/apikey), either:

1. **`.env` file** (before starting the dev server):
   ```
   VITE_GEMINI_API_KEY=your-key-here
   ```
   The start screen then shows a ✓ tick in the top-right corner.
2. **In the UI**: if no env key is set, the top-right corner of the start screen shows
   **"Insert Gemini API key:"** — paste the key and press Save. It's stored in your
   browser's localStorage (client-side only) and the field collapses to a ✓ tick. Click
   the tick to change the key later.

Without a key everything still works on the free engine — just slower.

### Generating and playing a game

1. Open the app. On the start screen, type a prompt describing your game, e.g.
   - `city runner in an underground bunker fallout 76 inspired`
   - `ice quest with yeti enemies`
   - `neon space sprint`
2. (Optional) Pick a game mode bubble — **Runner** or **Action Quest**. Leaving it
   unselected lets the prompt/randomizer decide.
3. Press **Generate** (or **Quick Start** for a random preset, or click a suggestion
   chip). The compiler terminal shows asset-by-asset progress, then the game starts.
4. Controls:
   - **Runner**: SPACE to jump.
   - **Action Quest**: WASD/arrows to move, SPACE to jump, E melee, F shoot (when
     enabled). Mobile devices get on-screen touch controls.
5. In game:
   - **Menu (top-right)** opens the Creator Panel: live physics/difficulty tuning,
     game type browser, export/import config, share link.
   - **Logo click** reopens the prompt screen to generate a new world.
   - On game over: **Play Again** or **Tweak Settings**.

### Dev tricks

- Force the free path with a key configured: run
  `localStorage.PM_FORCE_POLLINATIONS = '1'` in the console and reload.
- Inspect generation results: `window.__GAME_LIVE_CONFIG.assetMeta`.
- Share links (`#config=...`) replay a game config; they load raw fallback URLs directly
  (no post-processing), which needs the dev server's Pollinations proxy or an equivalent
  rewrite rule in production (see `vite.config.js`).

## Known limitations

- Enemy is static (animation machinery exists and is designed for reuse — deferred).
- Enclosed background pockets between a character's limbs can occasionally survive
  keying (deliberate trade-off that protects white details like visors).
- The free path is serial and slow (~1.5–2 min) due to Pollinations' one-at-a-time rate
  limit; that's an upstream constraint, not a bug.
- Pollinations blocks direct browser calls (Cloudflare Turnstile), so production hosting
  needs a `/api/pollinations/*` → `https://image.pollinations.ai` rewrite, same as the
  built-in Vite dev proxy.
